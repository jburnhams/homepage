# homepage: notes for agents

- The server is on [strata-python](https://github.com/jburnhams/strata-python) (FastAPI, `Settings`, `cli`, `tasks.Ticker`, `oslib`), Python 3.11+, run through uv (`bin/homepage` is `uv run --locked homepage`; `uv sync` builds `.venv` from `uv.lock`). Follow its AGENTS.md: `scripts/check` before every commit (lockfile, ruff, ruff format, pyright strict, ty, tests with coverage), types on everything in `src/`, no `--unsafe-fixes`. Dependencies move only with the owner's say-so.
- `bin/webauth` deliberately stays standard-library only and does not use strata-python: it is the login in front of every app, started by a launcher that knows nothing of uv, so a missing venv or a bad dependency bump must never be able to lock you out.
- `src/homepage/`: `settings.py` (`Settings`: `sites`, `state`, `repos`, `jobs`, `disks`, `perf`), `perfstats.py` (the Over time numbers), `snippets.py` (read the Caddy snippets), `collect.py` (all external calls go through the injectable `run`), `resources.py` (CPU/memory/process sampler reading `/proc`, injectable `proc=` for tests, run by a `Ticker`), `render.py` (HTML), `server.py` (FastAPI app, `StripPrefix` for Caddy's `/_home`), `cli.py` (`doctor`, `set`, `serve`, `print`). Tests are in `tests/unit/` (pytest): real HTTP against a real uvicorn for the server, a fake `/proc` on disk for the sampler, and a fake runner only for `systemctl` and `git`. `scripts/check` runs them.
- Escape everything that reaches the HTML (`render.e`); a test checks it. Never pass request data to a command.
- The page at `/` is a React + Tailwind front end in `web/` (rules in `web/AGENTS.md`), built to `web/dist/`, which is committed so the machine needs no Node. The server (`server.py`) only serves that, the JSON API and `/plain`, the old server-rendered no-JavaScript page (`render.py`), which is also the fallback when `web/dist` is missing. Keep `render.py` and the React page showing the same data; the "finding" line is computed once, in Python.
- `bin/webauth` is the login and the one file that must never be left broken: test it by hand (`curl` the login page and `/auth/check`) after any change, and note that a bad commit here can lock you out of every app.
- Sandbox test of the login (no password needed): make a temp JSON with `{"password_hash": hash_password('x'), "secret": <64 hex>}` (import `hash_password` from `bin/webauth`), run `WEBAUTH_CONF=<json> bin/webauth serve --port 8391`, then check `/auth/login` 200, `/auth/check` 303 without a cookie, POST wrong password 401, right password 303 + `webauth_auth` cookie, `/auth/check` with it 200.
- **This repo is public.** Machine specifics (hostnames, domains, addresses, user names, local paths, which jobs and disks, passwords, the owner's service names) do not belong here, in code, docs, tests, mocks or screenshots: they are settings (`homepage set`, `HOMEPAGE_*`, `examples/settings.json`) or webauth's `auth.json` (`examples/auth.json`), and the real values live in the owner's private config. Tests and mocks use placeholders (`myhost`, `/home/ada`).
- **Over time** (hour / day / week): `perfstats.py` reads the CSV files that `perf-sample` writes (main, `units-`, and `diskpaths-` for which disk and folder; a wait on disk is blamed on who moved data on the disks that were busy, never on bytes summed over all disks, which named users of a fast disk for waits on a slow one) (`~/.local/share/perf-stats/`, `homepage set perf PATH` or `HOMEPAGE_PERF` to change), serves them at `/api/perf?window=1h|24h|7d` (cached 30 s / 2 min / 10 min) and `render.perf_section` shows the 24 h window on the plain page. The verdict sentence is computed in Python, like the finding. Tests build small CSV folders (`tests/unit/test_perfstats.py`), so no sampler is needed. The React side is `web/components/over-time.tsx`; tab choice lives in `?range=`. Table columns are chosen by viewport in the component (`fit`), because strata-react's `Column.className` reaches cells but not headers.
