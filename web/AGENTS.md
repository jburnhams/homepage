# web/: front end rules

React 19 + Tailwind v4 on [strata-react](https://github.com/jburnhams/strata-react) (the npm package, `^` range in `package.json`; `npm update strata-react` to upgrade, then `npm run build`). Read `DESIGN.md` first, and strata-react's `CLAUDE.md` for its conventions.

- There are no local UI primitives. Button, Status, Metric, PageHeader, DataView, DataTable, LineChart, LinkCard, Meter, CompositionBar, ColorSchemeChoice, EmptyState, Skeleton come from `strata-react`; use them (and its other components) before writing markup, and put a gap in a strata-react issue rather than copying a component back in here.
- `className` at call sites is for layout only. Colour, type and radius come from tokens: `app/theme.generated.css` (palette.mjs, never hand-edited) and `app/globals.css` (status roles and the font). `strata-react/strata.css` supplies the namespace reset, type steps, motion and base layer; `@source` in `globals.css` lets Tailwind see the library's classes.
- `main.tsx` wraps the app in `ThemeProvider` (owns `.dark`), `StrataQueryProvider` and a `BrowserRouter` (DataTable keeps its sort in the URL). The status read is `useLoad` (`use-status.ts`) into `DataView`, which keeps the last readings under a `StaleNotice` when a refresh fails. Apps are `LinkCard`s, disks `Meter`s with shared limits, memory a `CompositionBar`; `ColorSchemeChoice compact` is in the header because there is no settings page.
- Numbers and times go through `format` (strata-react's `createFormat`, in `lib/format.ts`, which keeps only what is specific here: the server's 0-100 percentages and /proc's kibibytes). Disks are decimal (`format.bytes`), RAM is binary (`{ binary: true }`, GiB). Every status has a word.
- The server owns the data: it samples `/proc`, computes the finding and serves `/_home/api/status`. The UI only draws it and polls every 5 s through `usePoll` (paused while the tab is hidden, or by the person with `PauseButton`, which also says when it last read). Scheduled jobs are a `ScheduleTable`; "About this server" is `SystemPanel` on the server's `/api/system` (read by `use-system.ts` at the absolute `/_home/api/system`, like the status read, because the page is served at `/` and `/_home/` and `useSystemInfo` would put `add_web`'s `<base>` in front).
- `npm run check` (typecheck + build) and, with `UX_RESEARCH=<checkout of jburnhams/ux-research>`, `npm run lint` (slop-lint, operate mode). **`dist/` is committed**: rebuild it (`npm run build`) in the same commit as any change under `web/`, because the home server runs it without Node.
- Tests: `npm test` (Vitest + Testing Library + jsdom + MSW, `renderWithStrata` from `strata-react/testing`). Put the server into a state with `server.use(...)`, never `vi.mock` or a `fetch` stub. `npm run test:visual` builds then compares `tests/visual/baselines/` (status page in each state, light and dark, wide and phone; config in `strata-visual.config.ts`, handlers shared with the unit tests in `tests/mocks.ts`); `test:visual:update` rewrites them. The page uses the system UI font on purpose, so the config pins it (`systemFonts: { pin, files }`): Chromium gets a fontconfig whose only font is `tests/visual/fonts/DejaVuSans.ttf`, so baselines match on every Linux machine and CI. Playwright is pinned exactly: baselines belong to its Chromium, and CI (`.github/workflows/web.yml`: typecheck, tests, dist is current, visual) regenerates nothing, so update them with the same version and look at the diffs first.
- **Regenerating baselines locally**: `npm run test:visual:update` (Playwright's pinned Chromium; the font pin above does the rest), then look at the diffs. `npx strata-visual` first should show the states you did not touch as matching.
