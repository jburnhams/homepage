# web/: front end rules

React 19 + Tailwind v4 + shadcn-style components, copied in from `ux-research/ui-library` (Plinth). Read `DESIGN.md` first.

- `components/ui/*` are the shared primitives (Button, Status, Metric, PageHeader, DataView, DataTable, LineChart). Use them before writing markup; add new ones the same way (variants via `cva`, states in the type signature).
- `className` at call sites is for layout only. Colour, type and radius come from tokens (`app/theme.generated.css` is generated by `palette.mjs`, never hand-edited; `app/globals.css` holds the rest). Tailwind's stock palette and sizes are removed on purpose: use `type-*`, `rounded-surface`, the named colours.
- Numbers and times go through `lib/format.ts`. Every status has a word.
- The server owns the data: it samples `/proc`, computes the finding and serves `/_home/api/status`. The UI only draws it and polls every 5 s (paused while the tab is hidden).
- `npm run check` (typecheck + build) and, with `UX_RESEARCH=<checkout of jburnhams/ux-research>`, `npm run lint` (slop-lint, operate mode). **`dist/` is committed**: rebuild it (`npm run build`) in the same commit as any change under `web/`, because the home server runs it without Node.
